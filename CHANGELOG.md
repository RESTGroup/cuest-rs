# Changelog

## v0.1.0 -- 2026-10-09

Initial release of `cuest-cudarc`, the safe cuEST wrapper.

Enhancement:

- `CuestContext`: cuEST handle creation bound to a user [`cudarc`] stream,
  with handle options (JIT kernel cache directory and compile threads,
  quadrature limits), math mode, compute-capability target, runtime version
  queries and a binding/version check (`UnsupportedVersion` error).
- Safe objects with `Arc`-based keep-alives and cuEST's destruction order:
  `CuestAOShell`, `CuestAOBasis`, `CuestAOPairList`, `CuestOeIntPlan`.
  Host/device workspaces are allocated from the `...WorkspaceQuery` sizes and
  freed with the objects; parameters handles are created and destroyed around
  each call.
- One-electron integral computation on the plan: overlap (`S`), kinetic (`T`)
  and potential (`V`) matrices, each with an auto-allocating variant and a
  `*_into` variant, plus `CuestPotentialComputeOptions` (ffloat/JIT usage
  modes). Device buffers are checked against the context stream and against
  the matrix sizes the cuEST C API cannot validate.
- Typed attribute queries (`cuestQuery`): `CuestAttribute` markers for the AO
  shell and AO basis attributes, with infallible accessors cached at creation.
- `Xyz` geometry parsing (Angstrom) with Bohr conversion and the cuEST nuclear
  attraction charge convention, and cuEST's documented contraction
  coefficient normalization (`CuestShellSpec::normalized`).
- Tests: pure-Rust unit tests (CI-safe) and `#[ignore]`d GPU regression tests
  against pyscf reference values (`S`/`T`/`V` for H2/STO-3G and H2O/def2-SVP,
  regenerated by `tests/regression/gen_reference.py`).

[`cudarc`]: https://docs.rs/cudarc
